# Hotel Host Dashboard

Host 帳號登入／註冊後，未指定其他合法返回頁時會進入 `/host`。也可從個人選單的 **Host Dashboard** 開啟。User／Admin 不會看到 Host 管理內容；直接輸入後台網址仍會顯示權限提示，後端也會檢查角色和每間酒店的所有權。

| 頁面 | 用途 |
| --- | --- |
| `/host` | 所有自有酒店數、已發布酒店數、訂單總數與已確認訂單數 |
| `/host/hotels` | 新增草稿酒店、編輯名稱／地址／描述、送審／撤回／下架／封存 |
| `/host/rooms?hotelId=...` | 新增房型、編輯名稱／描述／基本價格、停用／啟用 |
| `/host/inventory?hotelId=...&roomId=...` | 按日期初始化庫存、修改每日價、可供應房數、封鎖數與停售 |
| `/host/bookings?hotelId=...` | 分頁查看自己酒店的住客姓名、入住日期、房型、金額與訂單狀態 |

第一次使用：

1. 在 Hotels 選 **Add hotel**，設定名稱、所在地、貨幣與 IANA 時區，儲存為 DRAFT。
2. 新增房型，設定每間入住人數、床數、實際房間數和基本每晚價格。
3. 在 Daily inventory 初始化可販售的日期。開始日包含、結束日不包含，最多 366 晚。重複初始化只新增缺少的日期，不覆蓋已訂房數、停售或自訂價格。
4. 上傳至少一張酒店照片、填寫描述，回到 Hotels 選 **Submit for review**。Admin 核准後才會公開；退回時會顯示修改原因，可修改後重新送審。
5. 在 Bookings 查看訂單與測試付款／退款狀態。付款與符合政策的取消由 User 在 My Bookings 操作，Host 不可自行取消住客訂單。

總覽由新增的 `GET /api/host/overview` 取得，只統計登入 Host 的酒店和訂單。總酒店數包含封存酒店；已確認訂單數包含所有 CONFIRMED 記錄，不代表即將入住數，也不是營收。後台不計算虛構收入。

送審、撤回、下架及封存均需額外確認。送審期間酒店、房型、圖片與庫存只讀，需先撤回才能編輯。已上架酒店修改基本資料後會回到草稿重新送審；既有預訂不受影響。ARCHIVED 是永久封存，無法重新發布或編輯；不會刪除歷史訂單。酒店 URL slug、國家、貨幣、時區，以及房型 code／容量／床數／實際總房數，依現有 API 規則建立後固定。

每日庫存中 Booked 只讀，由真正的預訂／取消交易更新。Host 不能手動改已訂房數，當日總量不可低於已訂＋封鎖，也不能超過房型實際房數。停售日期的可售量顯示為 0。

所有表單在使用者送出前不會寫入後端。POST、PUT 和 PATCH 使用 Cookie 與新的 CSRF token，重複點擊在請求處理中會被阻止。儲存失敗時保留輸入並顯示後端錯誤。401 會清除前端登入狀態並要求重新登入；所有資料僅由自有酒店 API 取得。

前端新增 `components/host/` 和 `services/hostApi.js`；後端總覽 Controller 與統計 Repository 方法已加入。重新啟動 Spring Boot 才能使用總覽 API。沒有新增示範帳號、修改現有角色或填入 Aiven 測試資料。圖片管理與 Admin 審核已接通；詳細初始化與流程見 [ADMIN.md](ADMIN.md)。此後台不提供 Host 分帳、營收或修改住客訂單功能。

部署時 SPA fallback 需包含 `/host` 和 `/host/*`，且不能將 `/api/host/*` 導向 React。現有 User 帳號不會自動升級為 Host；請使用註冊時選擇 Hotel Host 的帳號登入。
